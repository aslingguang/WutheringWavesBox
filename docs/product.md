# 产品需求

## 1. 产品定位

WutheringWavesBox 是面向 Windows PC 玩家的一体化本地工具。它负责聚合常用操作和数据分析，不修改游戏进程内存，不注入游戏，不绕过反作弊，不承诺任何非官方接口长期可用。

## 2. 目标用户

- 同一台电脑管理多个游戏账号的玩家
- 希望本地保存并分析抽卡记录的玩家
- 希望统一查看游戏版本、公告和激活码的玩家
- 希望通过一个入口启动和管理游戏的玩家

## 3. MVP 功能范围

### 3.1 游戏管理

- 自动扫描常见安装目录
- 手动选择游戏可执行文件或根目录
- 验证目录结构
- 读取本地版本（按官方启动器配置中已安装资源包的版本，而非基础版本）
- 查询远端版本并给出“最新、可更新、未知”状态
- 启动游戏，支持配置合法的启动参数
- “启动游戏”和“更新游戏”为独立按钮；版本检测失败或误判时仍可直接启动游戏
- 展示游戏进程状态和本次运行时长

### 3.2 账号档案与切换

- 创建、编辑、删除账号档案
- 账号档案至少包含名称、服务器、UID（可选）、备注
- 从当前游戏环境捕获可切换状态
- 切换前备份当前状态
- 切换失败时恢复备份
- 敏感内容通过 Windows DPAPI 或 Credential Manager 保存
- UI 和日志只显示脱敏摘要

### 3.3 抽卡分析

- 支持通过游戏日志/缓存中的 URL 导入
- 支持手动粘贴 URL 或导入标准 JSON
- 支持用户主动查看和复制完整抽卡 URL，以便导入其他分析平台
- 按 UID 和服务器隔离数据
- 支持角色、武器、常驻等卡池分类
- 展示总抽数、五星数量、平均出金、当前垫数和历史列表
- 幂等导入，重复记录不得重复落库
- 支持 JSON 导出和备份恢复
- 支持直观、详情、表格和版本总结四种查看方式
- 支持独立于软件全局主题的高对比度分析模式
- 支持按手机、桌面或当前窗口比例生成完整分析快照，并保存为 PNG 或复制到剪贴板
- 快照必须完整展开分析记录；不同主题下不得出现透明叠层、内容截断或不可读配色
- UID、历史链接、分页和快照设置使用顶层弹窗，不能被分析容器裁切或覆盖

完整抽卡 URL 可能包含临时认证参数。工具不得自动上传到第三方，不得写入日志或数据库；只有用户主动点击复制时才进入系统剪贴板，并在界面提示链接具有敏感性。

### 3.4 激活码

- 国服与国际服分别从可替换网页数据源获取激活码
- 展示来源、有效期、适用服务器和状态
- 一键复制
- 以区服和兑换码作为数据库唯一键，重复同步不得重复落库
- 本地记录已使用/未使用状态，来源更新不得覆盖用户状态
- 主页仅聚合展示未过期且未使用的兑换码
- 自动兑换必须单独评估接口稳定性和账号安全，MVP 不默认启用

## 4. 非功能需求

- Windows 10 22H2 和 Windows 11 x64 为首要支持范围
- 冷启动目标小于 3 秒（主流 SSD，不含在线请求）
- UI 操作不得被网络或文件任务阻塞
- Helper 崩溃不得导致 Electron 主进程崩溃
- 所有破坏性文件操作必须明确确认并可恢复
- 数据库升级必须使用迁移，不允许静默删除用户数据
- 默认中文，结构上支持英文国际化
- 深色、浅色和玻璃主题下应保持一致的组件层级、可读对比度和交互反馈
- 支持单张图片或文件夹轮换壁纸；壁纸读取由 Main 进程完成，Renderer 只接收受控数据 URL

## 5. 首版不做

- 游戏进程注入、内存修改和反作弊相关能力
- 自动修改高风险画质/帧率参数
- 云端账号凭据同步
- 自建账号密码登录系统
- 全量游戏下载安装器
- 插件市场和第三方脚本执行

## 6. 验收标准

- 全新安装后可以完成游戏目录配置并启动游戏
- 远端不可用时仍可离线启动和查看本地抽卡数据
- 两个账号可往返切换，失败测试能够恢复原状态
- 同一份抽卡数据导入两次后记录数不变
- UI 进程无法直接读取凭据明文
- 日志扫描不包含 token、cookie、登录票据或完整抽卡 URL

## 8. 主页快捷设置与版本同步

- 主页账户卡左侧提供可折叠的“游戏启动项”快捷设置区；折叠状态保存在本机。
- 快捷设置按安装项读取游戏 `GameUserSettings.ini`，支持全屏、无边框窗口、窗口模式和常用分辨率，游戏运行时禁止写入。
- 快捷设置管理从工具箱启动游戏时使用的 DirectX 渲染模式。
- 快捷设置提供“自定义参数”输入，按通用模板或账户模板保存用户填写的启动参数；参数追加在固定参数之后，可补充或覆盖显示、分辨率与渲染参数，启动前校验长度和控制字符，无效时阻止启动并提示原因。
- “检测更新”必须先通过 Helper 重新校验已有安装目录，将官方启动器写入的新本地版本同步到 SQLite，再查询官方版本并比较；本地版本取 `launcherDownloadConfig.json` 中已安装资源包的版本，避免把基础版本误判为旧版本。
- 游戏尚未生成画面配置时只提示用户先启动一次游戏，不主动创建不完整的 Unreal 配置文件。
- 快捷设置以通用模板为默认值；可按已导入账户显式启用独立模板，启用时复制通用模板，禁用后恢复使用通用模板。
- 游戏启动时先激活账户，再写入该账户最终生效的显示设置，并附加经过校验的 Unreal 显示参数与自定义参数，避免加载阶段恢复旧设置。

## 9. 全局选中态高亮

- 高亮颜色、边框位置和宽度使用统一主题令牌，覆盖应用内明确的选中态，不改变运行、错误、更新等状态提示。
- 用户可以分别控制主导航、标签页、选项与筛选、抽卡分析高对比度四个作用域。
- 主导航、标签页和选项可分别启用自定义高亮；未启用自定义时仍显示默认高亮。抽卡高对比度默认保留其专用橙色标记，仅在用户启用覆盖后使用全局高亮。
- 高亮标记默认使用 `#22aeb0`、`4px` 和左侧加底部边缘；当用户未选择任何边缘时，所有启用作用域自动回退到该默认标记。
- 鼠标悬停高亮独立于选中标记配置，按主导航、标签页和选项分别控制；未启用自定义时回退到默认悬停颜色与样式。
- 作用域设置保存在本机，并同时应用到主窗口和应用内弹窗。
- 选中前后控件的基础边框宽度必须保持一致；主导航不使用实体选中边框，可配置标记通过内部覆盖层绘制，不得改变控件尺寸。

## 10. 主页账户卡与统一下拉框

- 主页账户卡头像使用高质量多级缩放渲染，头像容器背景保持透明，避免高分辨率资源被浏览器一次性缩小后发糊。
- 结晶波片和结晶单质都显示到蓄满所需时间；结晶单质以结晶波片蓄满后的转换时间和单质剩余容量计算。
- 已协同库街区账号时，主页优先使用库街区角色数据补充共鸣者数量及周度游历；本地启动器数据仍作为网络或协同不可用时的降级来源。
- 共鸣者与周度游历使用库街区数据终端对应模块的官方本地图标，界面不依赖运行时远程图片加载。
- 抽卡分析打开时，若当前主页 UID 已有本地唤取记录，必须优先展示该 UID 的分析结果。
- 应用内的选项控件使用统一下拉框组件，包括主页快捷设置、抽卡快照与分页设置、账户档案、外观与行为设置及库街区角色选择。
- 主页快捷设置使用单一“游戏启动项”页，集中管理显示模式、分辨率和渲染模式；安装卡工具栏只保留安装检测与管理操作。
- 账户备注使用账户管理之上的通用子弹窗编辑，弹窗控件聚焦或悬停不得改变弹窗尺寸或产生临时滚动条。
- 库街区设置弹窗按功能分组保持紧凑信息密度；签到与补签开关在常规窗口使用双列布局，在窄窗口自动回退单列。
